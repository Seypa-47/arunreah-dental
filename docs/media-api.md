# CMS media API

`POST /api/admin/media` and `DELETE /api/admin/media` are private CMS routes.
They require the normal HttpOnly admin session cookie and `CMS_MANAGEMENT`
permission: `CMS_ADMIN` and `SUPER_ADMIN` are allowed; `RECEPTIONIST` receives
`403 FORBIDDEN`.

## Upload

Send `multipart/form-data` with these fields:

| Field      | Required | Values                                                   |
| ---------- | -------- | -------------------------------------------------------- |
| `file`     | Yes      | JPEG, PNG, or WEBP image, maximum 5 MB                   |
| `category` | Yes      | `clinic`, `branches`, `services`, `doctors`, `showcases` |

The Worker validates the declared MIME type and the image signature, then
generates a unique key. Clients must not construct R2 keys or send paths.

```json
{
  "success": true,
  "data": {
    "key": "doctors/uuid-profile.webp",
    "url": "https://media.example.com/doctors/uuid-profile.webp",
    "mimeType": "image/webp",
    "size": 245812
  }
}
```

`url` is `null` until `MEDIA_PUBLIC_BASE_URL` is configured. In staging and
production, set it to the HTTPS R2 custom-domain origin without a trailing
slash. It is public configuration, not a secret. The frontend should persist
and send the returned `key` in a domain update such as `photoKey`, `imageKey`,
or `coverImageKey`.

## Replacement

Upload the new image first, update the consuming CMS record with its new key,
and only then delete the old key. Every upload receives a new immutable key, so
browser/CDN caches do not serve a stale replacement. The upload endpoint never
deletes an existing object.

## Delete

Send JSON to `DELETE /api/admin/media`:

```json
{ "key": "doctors/uuid-profile.webp" }
```

Only keys generated by this media endpoint are accepted. Before R2 deletion,
the API checks clinic settings, branches, services, doctors, showcases, and
showcase sections. A referenced key returns `409 MEDIA_IN_USE`; only orphaned
objects can be removed. There is intentionally no public media-list endpoint.
